# API Subagents

**在 Codex 中使用自己配置的外部模型。** 一个 Windows 桌面 App 管理 API 连接：你可以让 Codex 把部分任务交给外部模型，也可以让外部模型直接处理 Codex 主对话。

适用系统：Windows 10/11 x64；使用系统 WebView2，无需安装 Node.js。模型服务和 API Key 由你提供，本项目不附带模型额度。

## 先选一种用法

| 模式 | 谁处理主对话？ | 外部模型做什么？ | App 需要保持打开？ |
| --- | --- | --- | --- |
| **插件委派** | 原来的 Codex 主模型 | 完成指定任务，返回建议；明确授权后也能修改文件、运行测试 | 不需要，安装并配置后可退出 |
| **挟持模式** | 你选择的外部模型 | 在 Codex 界面中直接回答和使用工具 | 需要，使用期间保持运行 |

**怎么选？** 想保留 Codex 主模型、只分出去一部分工作，选插件委派；想让自己购买的 API 服务承担主对话，选挟持模式。插件委派仍需要 Codex 主模型发起任务，不能绕过它的额度；挟持模式的模型请求按上游 API 计费。本工具不读取 Codex 套餐余额。

需要在 Codex 对话中生图时，保持文字主模型，并让插件的 `generate_image` 工具调用已保存连接中选中的 `gpt-image-*` 模型。图片保存到工作区固定目录，按上游计费；不要将图片模型选为主对话模型。[参数和限制](docs/usage.md#在-codex-对话中生成图片)。

## 工作原理

```text
插件委派：Codex 主模型 → 本地插件 → 指定的外部模型 → 建议 / 经授权的执行结果
挟持模式：Codex 主对话 → 本机 App 网关 → 外部模型 API → 流式回答返回 Codex
```

**插件委派**会读取 App 中保存的连接。默认只允许外部模型查看项目并提出修改建议，由 Codex 主任务检查后应用；不会让外部模型直接写文件或运行命令。选择执行模式后，插件才启动独立的 Codex worker，在指定工作区内执行。写入和联网需要分别授权，所选模型及上游也必须支持工具调用。这个过程不切换主对话的模型，无需开启挟持模式。

**挟持模式**会临时配置 Codex 的模型入口。重启 Codex 后，选中的模型请求进入只监听本机的带令牌网关；网关换成你配置的模型 ID 和凭据，再转发到上游。支持 Responses 的服务推荐使用 **Responses 透传**，其他接口由本地网关转换。关闭 App 时会关闭网关、恢复原来的 Codex 配置；异常退出后，下次启动会尝试恢复。

两种模式共用连接信息，但不是把 Codex 登录凭据发给外部服务。模型的工具、图片和思考等级是否真正可用，仍取决于上游支持。[查看完整流程图](docs/images/how-it-works.png)。

## 开始使用

### 1. 安装并保存连接

从 [Releases 下载 Windows 安装包](https://github.com/U109/api-subagents/releases/latest)，安装并打开 App。点击「添加连接」，填写 API 地址和 Key；新连接默认使用 Responses 透传及流式，请确认上游支持 `/responses`。旧连接的其他协议保持兼容。然后在「模型选择」勾选模型、设定默认模型并保存。列表里没有的模型 ID 可以手动添加。

**一个连接可以有多个模型**，共用地址和 Key。保存后可在 Codex 中直接选择「连接名 · 模型名称」；「跟随 App 选择」才会随着 App 的默认模型变化。模型列表或默认思考等级改变后，要重启 Codex 刷新。

### 2A. 使用插件委派

在 App 的「插件管理」点击「安装到 Codex」，然后在 Codex **新建对话**。可以这样描述任务：

> 把这个目录的重复修改交给我配置的外部模型。先让它提出建议，你检查差异并运行必要测试。

默认只返回建议。需要模型直接修改文件和运行测试时，明确选择执行模式和 `workspace-write`；默认不允许联网。执行产生的改动不会自动回滚，应检查实际 diff 和测试结果。安装完成后，普通插件可以在 App 关闭时运行。

需要在 Codex 对话里生图时，继续选文字主模型，使用插件的 `generate_image` 工具调用已保存连接中的 `gpt-image-*` 模型；图片保存到工作区固定目录并按上游计费，不要把生图模型切为主对话模型。[参数和限制](docs/usage.md#在-codex-对话中生成图片)。

### 2B. 使用挟持模式

选中已保存的连接，开启「挟持模式」，然后**完全退出并重启 Codex**。在模型列表选择该连接的模型，或选择「跟随 App 选择」。每次重新开启模式，本机网关的端口和令牌都可能变化，因此不能只在第一次开启时重启。

使用期间保持 App 打开。挟持模式会临时接管所有旧对话的提供商入口，包括内置 OpenAI、非默认自定义提供商和历史中仍保留的已删除身份；旧的真实模型名跟随 App 当前选中的连接。退出模式或关闭 App 时恢复原来的提供商、地址、凭据和默认选择，移除临时补齐的身份。开关模式后均需完全退出并重启 Codex。仅读取提供商元数据，不改写聊天记录；关闭后不要继续选择 `api-subagents/…` 外部模型别名。

## 费用、安全与常见问题

- **费用怎么算？** 外部模型的请求按你的上游服务计费；插件委派还需要 Codex 主模型参与。不保证一定比直接使用主模型省 token。
- **数据在哪里？** 连接、Key、任务记录和 Codex 配置备份保存在本机，不进入 Git 或安装包。委派的文件内容和工具结果会发送给你选定的上游，请不要交出无权分享的数据。
- **模型没有出现在 Codex？** 先确认连接已保存、模式已开启，再完全退出并重启 Codex。插件更新后则需在 Codex 新建对话。
- **出现 `Upstream request failed`？** 检查 App 是否仍在运行、当前对话的提供商和所选模型是否匹配；不要只在旧对话中切换模型名。详见[连接与排错](docs/usage.md#出现-upstream-request-failed)。
- **换回账号登录后旧对话一直重连？** 先关闭挟持模式，完全退出并重启 Codex，在旧对话中选择账号支持的官方模型。新版 App 会自动升级未改动的旧版停用占位；重新开启模式前也需要重启 Codex。
- **某个思考等级不能用？** 菜单列出可传递的选项，不保证上游模型支持；最终以模型服务接受的参数为准。

在 App 中「检查更新」可更新桌面版；插件可在「插件管理」中单独更新。安装包目前未签名。
