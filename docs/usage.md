# 连接与使用

## 配置连接

| Tab | 内容 |
| --- | --- |
| 连接信息 | 连接名称、接口类型、API 地址、Key；重命名也在此处完成 |
| 模型选择 | 搜索并勾选模型、行内设置默认、切换全部／已选、手动添加 ID 与思考等级 |
| 任务分工 | 描述适合委派的工作，帮助 Codex 选择连接 |
| 高级设置 | 流式响应、输出长度、并发和超时 |

连接名称支持中文、大小写、空格和符号，不限制格式或长度；仅需填写非空且不重复的名称。复制保留完整名称并保存独立副本，其他连接草稿保持不变。删除需要在弹窗中确认。

修改 API 地址或接口类型后，Key 留空会继续使用已保存的 Key；填写新 Key 则替换原值。已设置的 Key 环境变量仍优先使用，无需因地址变化而清除。

| 接口 | API 根地址示例 |
| --- | --- |
| Responses 透传（推荐 CPA） | 上游须支持 `/responses`；CPA 常用 `http://127.0.0.1:8317/v1` |
| Responses | `https://api.openai.com/v1`，或支持 Responses 的 CPA 地址 |
| Claude 原生 | `https://api.anthropic.com/v1` |
| Gemini 原生 | `https://generativelanguage.googleapis.com/v1beta` |

测试连接会发送一条简短请求，可能产生少量费用。模型还需要支持工具调用才能完成编码任务；仅通过连通性测试不代表所有能力都兼容。

思考等级可选服务默认、none、minimal、low、medium、high、xhigh，具体档位需模型支持。服务默认不强加推理参数；Codex 中手动选择优先于 App 默认，修改目录默认值需重启 Codex。较高等级通常更慢、用量更多；Claude 旧模型与 Gemini 2.5 使用预算映射，预算不会突破配置的最大输出长度。Claude 预算式思考要求最大输出长度至少 1025。

默认流式接收，不支持流式的服务可切换为普通响应。首个数据默认等待 180 秒，响应空闲默认 120 秒，任务总时限默认 15 分钟。心跳只刷新空闲时间。失败或断流不会由本工具自动重复生成请求。

也可从环境变量读取 Key。该变量需存在于实际请求进程中：挟持模式是桌面 App，插件模式是 Codex 启动的 MCP 进程。插件使用时，将变量名加入已安装插件 `.mcp.json` 的 `env_vars`；升级会保留名单。

## 插件委派

在「插件管理」查看实际安装版本与 App 附带版本。首次安装可直接使用附带版本；点击「检查插件更新」，再点击「更新至…」可独立下载并安装新版插件，无需更新 App。安装后在 Codex 新建对话，已有对话仍使用原来的插件进程。已安装版本更高时，旧 App 不会用附带插件覆盖它。

插件更新从本项目公开 Release 获取，下载后检查大小、SHA-256、最低 App 版本和包内文件清单。更新保留本机连接、Key、个人插件市场和环境变量透传设置；校验失败会停止安装，关闭 App 不会自动安装更新。

在 Codex 中说明边界，例如：

> 把 utils 目录中批量补中文注释的工作交给 commenter，只读取有关文件。你检查修改片段并运行必要测试。

外部模型只能使用受限文件工具读取项目、提出修改建议；它不能执行命令或直接写入文件。Codex 检查并应用建议。返回默认精简，完整记录保存在本机，需要时再读取。

委派适合重复量较大的明确任务。简单问答和小改动会增加调度成本，流式响应本身也不会减少 token。

## 挟持模式

在「模型选择」点击「刷新列表」，搜索名称或 ID，直接勾选要在 Codex 中显示的模型。「已选」只显示勾选项；点击行内「设为默认」可更换插件委派和「跟随 App」使用的模型。更换默认会保留原默认与其他已选模型，普通勾选不会改变默认值。

服务返回的模型列表不正确时，点击已选模型行内的铅笔图标，修改「上游模型 ID」。这就是实际发送给上游的 `model` 值，支持手动修正，最多 200 字符。修改会替换当前选中项，保留其默认身份和其他选择；刷新服务列表不会覆盖修正结果。保存后重启 Codex，并在模型列表中重新选择修改后的模型。

「显示名称」单独控制 App 与 Codex 的列表文字，支持中文，最多 80 字符，不作为请求的模型 ID。留空或点击「恢复默认名称」后保存修改可还原；只改显示名称时，实际调用和旧对话路由保持不变。

默认模型始终勾选，每个连接还可额外选择 32 个模型。未出现在服务目录中的 ID 可通过「手动添加」弹窗填写；刷新失败或服务不再列出某个模型时，已有配置仍保留。列表中的模型共享该连接的地址、Key 和默认思考等级；不同服务或凭据请建立不同连接。修改后点击「保存配置」。

打开连接标题旁的「挟持模式」开关，重启 Codex 后即可看到这些模型。修改列表也需要重启 Codex 刷新，但列表加载后可直接在同一对话中切换模型，无需重新开启 App。选中另一个已保存连接时，点击「切换到此连接」更新默认值；关闭开关会恢复原有配置。Codex 模型列表中：

- **跟随 App 选择**：后续请求使用 App 的默认连接，切换 App 连接无需再次重启。
- **连接名 · 模型名称**：使用该连接与列表中的模型；未命名时显示模型 ID。同名模型属于不同连接时分别显示，使用各自凭据；切换不会改写插件委派的默认模型。

左侧绿色「挟持中」标记表示最近一次请求使用的连接；尚无请求时显示默认连接。开启本身不会发送模型生成请求。

旧配置无需重建，仍显示原默认模型；旧连接别名继续可用。已从列表移除的模型会停止接受新请求，重启 Codex 后从选择菜单消失。连接重命名后，请在 Codex 重新选择新连接名对应的模型。

一个 worker 对应一个连接，可以共用同一地址和 Key 勾选多个模型。保存并刷新 Codex 目录后，直接在 Codex 切换「连接名 · 模型名称」即可，不必回 App 更改默认。具体模型均使用固定标识，改变 App 默认值不会改变其路由；旧版仅包含连接名的别名继续跟随该连接默认模型。

本地网关仅监听回环地址，以随机令牌鉴权。Responses 接口逐块透传，仅替换模型别名和凭据；只有其他接口才由本地 CPA SDK 转换，Codex 的登录信息和本地令牌不会转发给模型服务。原生 Responses 接口兼容性通常更完整，其他协议仍取决于模型的工具能力。当前目录声明文本输入，不宣称支持图像或原生网络搜索。非 Responses 服务不支持 /responses/compact，Codex 使用本地上下文压缩。

**兼容策略**：CPA 推荐在连接信息中选择「Responses 透传」，将模型兼容交给上游；透传不使用厂商兼容策略。选择 Chat Completions 时，才在模型编辑窗口配置兼容策略，官方地址自动识别，自定义地址默认通用；直接转发厂商 API 时可指定 Gemini、DeepSeek、Kimi、豆包、MiniMax、GLM 等策略。策略同时用于插件和挟持模式；各型号思考开关与档位限制见[模型兼容说明](model-compatibility.md)。

**上下文长度**：在「模型选择」点击已选模型右侧的编辑按钮，填写该模型实际支持的上下文 tokens，保存配置并重启 Codex。每个模型独立保存，自动压缩阈值为容量的 90%；例如填写 `128000`，约 `115200` tokens 时压缩。未知容量留空使用保守默认 `32768`，不会根据模型名称猜测服务上限。「高级设置」的最大输出长度用于插件委派和旧接口转换，不会扩大上下文；Responses 透传的输出限制由 Codex 请求与上游决定。容量应以实际 API 服务的限制为准，填大不能增加模型能力，较长历史也可能增加请求费用。

挟持模式会暂存 Codex 顶层的上下文与压缩阈值覆盖项，让模型目录中的独立容量生效；关闭后恢复原值。其他 Codex profile 或启动参数仍可能覆盖目录。使用「跟随 App」切换到容量不同的模型后也需重启 Codex 刷新；在 Codex 中直接选择各个模型可使用其各自容量。

**思考标签与断流**：`<thinking>` / `<think>` 如果出现在普通消息里，说明收到的是正文文本；它们本身不是 Codex 的思考事件。标准思考字段会单独转换，普通正文不会用正则过滤，以免破坏引用和代码。透传不会额外插入限制标签或进度语言的提示，上游必须正确返回思考事件。Responses 透传不合成完成或失败事件；网络错误直接中止传输，是否缺少完成事件由 Codex 判断。本地挟持提供商使用 HTTP/SSE 并禁用 WebSocket，出现 WebSocket 错误时还需检查该对话实际使用的提供商与上游日志。

关闭模式会恢复之前的模型设置，保留其他 Codex 设置的新修改。点击窗口右上角关闭时，会自动关闭挟持模式、取消进行中的模型请求并退出，无需先手动关闭开关。有未保存修改时，页面内弹窗提供「继续编辑」和「放弃修改并退出」。插件安装或配置操作进行中时，会提示等待完成。

若恢复失败，App 会保持运行并显示具体原因，保留本机备份，修复后可再次关闭。异常退出后，下次启动会尝试恢复。若提示托管提供商被手动修改，备份会保留，避免覆盖用户编辑。模式运行时请勿移动数据目录；使用其他 Codex 配置 profile 时，其覆盖项可能优先于此处的默认设置。

关闭后保留一个无密钥、无活动服务的提供商占位，因此旧对话仍可打开查看；要继续使用其中的外部模型，请重新开启模式。升级后打开 App 会修复旧版本遗留的 `Model provider api_subagents not found`，然后重新打开报错对话即可，不修改聊天记录。

主对话内容、工具结果和代码会发送给所选模型服务。两种模式均使用外部 API 独立计费，本工具不读取套餐剩余额度。

## 本机数据

| 内容 | 默认位置 |
| --- | --- |
| 连接与 Key | `%LOCALAPPDATA%\CodexApiSubagents\models.json` |
| 委派记录 | `%LOCALAPPDATA%\CodexApiSubagents\tasks\` |
| Codex 配置备份与模型目录 | `%LOCALAPPDATA%\CodexApiSubagents\codex-*.json` |
| 插件运行程序 | `%LOCALAPPDATA%\CodexApiSubagents\runtime\` |
| 已安装插件 | `%USERPROFILE%\plugins\api-subagents\` |

`API_SUBAGENTS_HOME` 可指定数据目录，`CODEX_HOME` 可指定 Codex 目录。Key 和备份仅保存在本机；Git 与安装包不包含这些数据。备份可能包含原 Codex 配置中的私人字段，应和 Key 一样保管。
