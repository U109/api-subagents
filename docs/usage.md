# 连接与使用

## 接入配置

「接入配置」管理主对话接入的连接组合和模型范围。左侧使用常驻滚动列表，右侧编辑当前配置；窄屏上下排列但保持同页。查看配置不会切换正在运行的配置。「我的连接」同样采用列表与编辑器同页布局，切换条目保留各自草稿。侧栏分隔线中部的拉手可收起／展开导航。

## 用量统计

「用量统计」提供概览、分析、请求明细和价格统计四个页签，可按时间、连接、模型和调用来源筛选。数据来自经过本应用的原始上游响应，不读取 Codex 套餐余额；安装新功能之前的消耗不能从旧任务轮数反推。

- 主对话接入、提案型子代理、执行型子代理和图片生成记录到同一本地账本；连接测试可单独查看，默认不混入业务总览。
- 一次业务请求与上游重试尝试分别记录。同一请求的已知用量合计展示，未上报或无法观测的字段使用 `—`，不补零，也不按回答字符数猜测。
- 缓存和推理是输入／输出的子集，拆分时避免重复相加。缺少细分字段的记录不能用于完整分类占比。
- 平均输出 TPS 使用已上报输出 Token 与相应请求耗时计算，是本地观测值，不代表供应商内部生成性能。
- 价格由用户配置，单位为 USD / 百万 Token。未定价或缺少必要缓存字段时费用保持未知；请求开始时保存费率版本，修改价格不会静默重算历史。估算不包含未配置的工具等额外收费，真实费用以供应商账单为准。

用量保存在应用数据目录的 `usage/records/`，按 UTC 日期和尝试 UUID 独立原子写入，桌面与多个 worker 可共享读取；费率使用独立 `usage/prices.json`。不保存提示词、回答、真实 Key、授权头或上游错误正文。关闭接入／重启应用不清零历史。查询最多 31 天、单次最多一万条尝试，超过时应缩小范围；异常关机可能丢失尚未关闭的请求记录，磁盘或格式异常会显示统计降级。

用量观测不会为补统计继续读取、重发请求或修改返回 JSON / SSE。流尾帧未提供用量、超出观测预算或编码不可读时，统计可能不完整。

1. 在「我的连接」中添加连接、选择可用模型并保存。
2. 新建接入配置，勾选其中包含的连接，在「Codex 模型预览」中选择此配置实际要接入的模型，并星标一个配置默认模型。
3. 「仅保存」只保存配置；「保存并启用」或「启用此配置」才更改 Codex 接入。连接的模型勾选和星标不会被配置中的选择修改。

例如配置 A 选择 cpa＋worker、配置 B 选择 cpa＋review，启用 A 后只向 Codex 提供 A 所选的具体模型。模型预览中的选择只作用于当前配置，不会回写共享连接或自动扩大其他配置。

顶部总开关恢复最后明确启用的配置，不采用当前正在查看的配置。关闭后若修改了连接参数，需要明确重新启用配置；密钥轮换不要求重新选择范围。删除运行配置或其中的连接会先恢复 Codex 并关闭接入；恢复冲突时停止删除，不自动选择另一个配置。首次启动没有示例连接或自动启用的配置；旧配置会迁移为未启用的默认配置。

## 配置连接

| Tab | 内容 |
| --- | --- |
| 连接信息 | 连接名称、接口类型、API 地址、Key；重命名也在此处完成 |
| 模型选择 | 搜索并勾选模型、星标设置连接默认、拖动排序、切换全部／已选、模型设置、手动添加 ID 与思考等级 |
| 任务分工 | 描述适合委派的工作，帮助 Codex 选择连接 |
| 高级设置 | 自定义参数覆盖开关、流式／完整响应、输出长度和超时 |

「我的连接」集中展示连接目录，侧栏不再展开单独连接；点击连接进入四页签。保存按钮只保存对应连接，其他连接与配置的未完成草稿不受影响；还原也仅恢复当前连接。复制位于详情标题的图标或连接目录右端的更多菜单中，删除仍需确认。

连接名称支持中文、大小写、空格和符号；界面最多填写 60 个字符，名称需非空且不重复。复制先创建独立未保存草稿，保存后才写入本机配置；其他连接草稿保持不变。重命名使用稳定连接身份，不破坏接入配置中的引用。删除需要在弹窗中确认。

修改 API 地址或接口类型后，Key 留空会继续使用已保存的 Key；填写新 Key 则替换原值。已设置的 Key 环境变量仍优先使用，无需因地址变化而清除。

正在运行的接入使用明确启用时的参数快照；若连接地址或协议改变，不会把新的 Key 转发给旧快照地址，需要重新启用。复制草稿同样禁止跨已改变的来源地址静默复用密钥。

| 接口 | API 根地址示例 |
| --- | --- |
| Responses 透传（推荐 CPA） | 上游须支持 `/responses`；CPA 常用 `http://127.0.0.1:8317/v1` |
| Responses | `https://api.openai.com/v1`，或支持 Responses 的 CPA 地址 |
| Claude 原生 | `https://api.anthropic.com/v1` |
| Gemini 原生 | `https://generativelanguage.googleapis.com/v1beta` |

测试连接会发送一条简短请求，可能产生少量费用。模型还需要支持工具调用才能完成编码任务；仅通过连通性测试不代表所有能力都兼容。

思考等级可选服务默认、none、minimal、low、medium、high、xhigh、max、ultra，具体档位需模型支持。max/ultra 需要支持字符串推理档位的新版 Codex；目录仅声明可传递参数，不保证上游支持。Responses 和通用 Chat 协议保留所选值；受限厂商策略按其最高档位折合，预算式协议的 max/ultra 沿用 xhigh 预算上限。服务默认不强加推理参数；Codex 中手动选择优先于 App 默认，修改目录默认值或更新档位列表后需重启 Codex。较高等级通常更慢、用量更多；Claude 旧模型与 Gemini 2.5 使用预算映射，预算不会突破配置的最大输出长度。Claude 预算式思考要求最大输出长度至少 1025。

本地模拟集成测试确认：Codex CLI `0.155.0-alpha.16` 能列出 max/ultra，但选择 ultra 时发送的 `reasoning.effort` 为 max。插件不会将收到的 max 猜测还原成 ultra；直接收到 ultra 时，Responses 和通用 Chat 协议仍保留 ultra。可选档位与最终上送参数应分别核验，不能仅凭菜单判断模型实际使用的强度。

默认流式接收，不支持流式的服务可切换为普通响应。首个数据默认等待 180 秒，响应空闲默认 120 秒，任务总时限默认 15 分钟。心跳只刷新空闲时间。

主对话的 Responses 透传仅在收到 502／503，或安全流在正文、工具内容交付前返回暂时性失败时，最多恢复三次，等待 2／15／45 秒；服务要求更长等待时遵循其要求，超过一分钟则不自动恢复。连接错误、已经交付内容的断流、压缩请求和插件执行请求不重放；存在持久会话、后台请求或未知／服务端执行工具时，不对流前导失败自动重放。恢复沿用原模型、凭据和请求时限，取消立即终止；上游仍可能对尝试计费。其他接口不会由本工具自动重复生成请求。

新连接的「自定义参数覆盖」默认关闭：实际使用 4096 tokens、流式响应及上述超时默认值。开启后应用填写值；关闭只停止应用覆盖，不清空填写值，重新开启可恢复。「恢复默认」关闭覆盖并重置填写值。旧配置没有这个开关时仍沿用已保存参数，不静默改变运行行为。思考等级和模型独立容量／输出额度不由此开关重置。当前不提供任务并发数配置。

也可从环境变量读取 Key。该变量需存在于实际请求进程中：挟持模式是桌面 App，插件模式是 Codex 启动的 MCP 进程。插件使用时，将变量名加入已安装插件 `.mcp.json` 的 `env_vars`；升级会保留名单。

模型设置可填写自定义插件输出额度；留空使用自动策略，旧配置中的上游默认或厂商预算策略仍被保留。自动模式会按当前接口匹配已核实预算；请求已有额度时不覆盖，压缩请求不添加，未知型号不会猜测额度。[规格与设置说明](model-output-limits.md)

模型目录通过左侧六点手柄进行鼠标或触屏拖动，也可聚焦手柄后按空格抓取、上下方向键移动、空格放下或 Escape 取消；右端菜单保留上移／下移。筛选时只重排可见槽位，隐藏模型位置、勾选和默认项不变。连接目录顺序保存后保留；接入配置的默认和模型范围仍需要明确启用后才影响 Codex。

「模型设置」内只有一个上下文设置开关和数值输入。已知原生容量默认采用 `min(原生容量, 256K)`；关闭开关使用模型原生容量，未知容量不编造数值。设置和默认操作都在模型行右端，不再显示「声明容量／实际采用」列。连接中取消勾选默认模型时，由剩余首个已选模型接替；接入配置中移除默认模型后，需要重新星标默认项，不会静默代选。

## 应用更新

顶部「检查更新」打开原生模态弹窗，不切换页面，也不丢失连接、页签或草稿。关闭弹窗不会取消后台检查或下载；「取消当前操作」才会中止网络请求，不能取消已经开始的安装。取消或校验失败的包不可安装，重新检查失败则仍保留此前完整校验的已下载包。

检查和下载期间，文字前显示旋转等待图标；进度与完成状态来自实际后台操作，不用定时器模拟。减少动态效果设置会停用旋转，但保留等待文字。

「打开时自动检查」仅控制打开更新弹窗时是否查询固定发布源，不在启动时联网、不自动下载或安装。「跳过此版本」只作用于当前已验证版本，新版本仍会提示。两项偏好保存在本机更新缓存目录。更新内容以纯文本展示；安装前须保存或放弃全部草稿，等待配置请求和插件安装结束，后台还会重新校验包大小与 SHA-256。

## 插件委派

委派和等待工具默认一次阻塞等待最多 10 分钟，任务完成立即返回；插件宿主工具超时为 11 分钟，给结果返回预留余量。有独立工作可做时使用 `wait_ms: 0`，先完成独立工作，再使用默认长等待。等待超时不取消或重启后台任务，应继续使用同一个 `task_id`，不要反复短轮询或重新委派。这些设置仅作用于本插件的 `delegate_task` / `wait_task`，不修改 Codex 原生 `wait_agent`，也不保证具体额度节省比例。

更新时需一起更新 worker、`.mcp.json` 和技能说明，并在新对话中加载。若宿主仍提前终止长等待，应先检查实际加载的插件版本和宿主超时配置，不要回退为持续短轮询。

在「插件管理」查看实际安装版本与 App 附带版本。首次安装可直接使用附带版本；点击「检查插件更新」，再点击「更新至…」可独立下载并安装新版插件，无需更新 App。安装后在 Codex 新建对话，已有对话仍使用原来的插件进程。已安装版本更高时，旧 App 不会用附带插件覆盖它。

插件更新从本项目公开 Release 获取，下载后检查大小、SHA-256、最低 App 版本和包内文件清单。更新保留本机连接、Key、个人插件市场和环境变量透传设置；校验失败会停止安装，关闭 App 不会自动安装更新。

在 Codex 中说明边界，例如：

> 把 utils 目录中批量补中文注释的工作交给 commenter，只读取有关文件。你检查修改片段并运行必要测试。

默认的 `proposal` 模式只允许外部模型使用受限文件工具读取项目、提出修改建议，不能执行命令或直接写入文件；由主任务检查并应用。返回默认精简，完整记录保存在本机，需要时再读取。

### 执行型子代理：直接改文件和运行测试

`execution_mode: codex` 使用独立的 Codex App Server worker。它不是把外部模型塞进原生 v2 的加密任务转交，而是将完整明文任务直接提交给隔离的 Codex 会话。**不限定 DS/GLM**：所有已配置连接及其已选模型都可使用，复用 Responses、Chat Completions、Anthropic Messages 和 Gemini 适配；模型及上游仍须兼容工具调用，连通性成功不代表所有编码能力都可用。

无需开启挟持模式，也无需保持桌面 App 打开；本机必须有支持 App Server 的原生 Codex CLI。Windows 会自动查找 PATH 和 Codex Desktop 的版本目录；找不到时可设置 `API_SUBAGENTS_CODEX_BIN` 为 `codex.exe` 的绝对路径，然后重启加载插件的 Codex。执行过程不修改主对话的 provider 或个人 `config.toml`。

可在新对话中这样说：

> 使用 API Subagents 的执行模式，让我指定连接中的模型直接完成这个修改并运行相关测试。允许修改当前项目，不允许联网。保留我已有的改动，结束后检查实际 diff 和测试退出码。

工具参数示例（先用 `list_models` 查询真实名称，不要照抄占位符）：

```json
{
  "model": "已配置的连接名称",
  "model_id": "该连接 availableModels 中的模型 ID",
  "execution_mode": "codex",
  "access": "workspace-write",
  "network_access": false,
  "workspace": "C:\\Projects\\your-project",
  "task": "修改指定模块，保留现有改动，运行相关测试，报告修改文件、执行结果与阻塞项。",
  "max_steps": 20,
  "wait_ms": 0
}
```

- `model` 仍表示连接名称，新增的 `model_id` 可选该连接中的任意已选模型；省略时用默认模型，不改变保存的默认值。未配置模型会拒绝，不会自动换连接或模型。
- `access` 默认 `read-only`。需要直接修改文件或产生测试产物时显式选择 `workspace-write`；不提供全盘写入、自动提权或自动审批。执行权限独立于父会话，主模型必须遵守用户授权和父任务权限，不得借 worker 绕过限制。
- 命令联网默认关闭。确需下载依赖时，仅在用户授权后设置 `network_access: true`，且必须使用 `workspace-write`。权限不足或需要交互时返回失败，由主任务处理。沙箱限制写入/联网，不保证工作区外文件完全不可读；不要委派未经授权的秘密或私有数据。
- 每个 worker 使用私有临时 `CODEX_HOME`，不继承主任务 Key 环境变量，也不在该目录写入真实供应商 Key；凭据由 Go 网关持有。文件内容与工具结果仍会发送给所选上游。个人 shell/Git 配置和自定义环境不会完整继承，需要相应环境的测试应明确说明前提。
- `max_steps` 在此模式中限制模型请求数（1–30，默认 8），不是 shell 命令数；另受连接的任务总超时约束。
- worker 直接操作指定工作区，没有自动 worktree、合并或回滚。同一 MCP 进程会拒绝与写入任务目录重叠的活动委派；其他进程及主任务的编辑不在此锁范围内。并行写入应使用不同 worktree。
- 结果标记 `changeDelivery: workspace`，包含命令状态、退出码和补丁事件路径；**不返回 applyCommand，不要重复应用**。`changedFiles` 不包含所有可能由 shell 写入的文件，应结合实际 diff 验收。任务完成不等于所有测试通过，需检查退出码。
- 取消、失败和超时可能留下部分修改，不会自动回滚；会关闭临时网关并回收 worker 进程树，但不保证上游计费立即停止。执行记录保存在本机任务目录，临时 home 正常结束后清理；清理失败会在结果中提示。
- 此版本执行模式暂不支持 `continuation_id`；等待原任务结束后，可依据实际工作区状态派发新的完整任务。该 worker 也不是主任务里的原生 `spawn_agent` 子线程，不承诺完全相同的 UI。

委派适合重复量较大的明确任务。简单问答和小改动会增加调度成本，流式响应本身也不会减少 token。

### 在 Codex 对话中生成图片

保持 Codex 的文字主模型，在新对话里要求使用 API Subagents 的 `generate_image` 工具。先在连接中勾选 `gpt-image-*` 生图模型；`model` 填连接名称，`model_id` 可填该连接已选的生图模型 ID（仅选中一个时可省略）。Responses 或 OpenAI 兼容连接会使用已保存的地址和 Key 请求 `/v1/images/generations`，**不把生图模型作为 `/v1/responses` 主模型**。上游还需允许该模型与图片专用接口。

```json
{
  "model": "你的连接名称",
  "model_id": "gpt-image-2.5-sunburst",
  "prompt": "画一只橘猫",
  "workspace": "C:\\Projects\\your-project",
  "size": "1024x1024",
  "quality": "low"
}
```

每次调用生成一张图并按上游价格计费，不自动重试；省略尺寸/画质时发送 `1024x1024` / `low`。尺寸可选 `1024x1024`、`1536x1024`、`1024x1536`；画质可选 `low`、`medium`、`high`、`auto`，`xhigh`、`max` 仅限 `gpt-image-2.5-sunburst`。尺寸是上送参数，最终尺寸须以实际图片为准，上游未必严格遵守。图片只能保存到指定已有绝对工作区的 `api-subagents-images/` 内，返回绝对路径和可用时的预览。响应、文件与预览均有大小限制，超时或取消不自动重新发起请求；已经发出的请求是否收费以实际上游为准。此工具暂不支持图片编辑。安装更新的 worker 后，在 Codex **新建对话**加载新工具；已有对话不会自动获得新工具。

## 挟持模式

在「模型选择」点击「刷新」，搜索名称或 ID，直接勾选要在 Codex 中显示的模型。「已选」只显示勾选项；点击行内星标可更换插件委派和主对话接入的默认模型。更换默认会保留原默认与其他已选模型，普通勾选不会改变默认值。

服务返回的模型列表不正确时，点击模型行内的设置图标，修改「上游模型 ID」。这就是实际发送给上游的 `model` 值，支持手动修正，最多 200 字符。修改会替换当前选中项，保留其默认身份和其他选择；刷新服务列表不会覆盖修正结果。保存后重启 Codex，并在模型列表中重新选择修改后的模型。

「显示名称」单独控制 App 与 Codex 的列表文字，支持中文，最多 80 字符，不作为请求的模型 ID。留空或点击「恢复默认名称」后保存修改可还原；只改显示名称时，实际调用和旧对话路由保持不变。

每个连接最多选择 33 个模型（包含默认模型）。未出现在服务目录中的 ID 可通过「手动添加」弹窗填写；刷新失败或服务不再列出某个模型时，已有配置仍保留。列表中的模型共享该连接的地址、Key 和默认思考等级；不同服务或凭据请建立不同连接。修改后点击「保存配置」。

打开连接页上方的「主对话接入」开关，默认选择当前连接的星标模型，重启 Codex 后即可看到这些模型。修改列表也需要重启 Codex 刷新，但列表加载后可直接在同一对话中切换模型，无需重新开启 App。已开启时，选中另一个已保存且无修改的连接会自动将该连接的星标模型设为默认选择；选中草稿不会接入，保存完成后再切换。其他连接的草稿不参与接入，关闭开关会恢复原有配置。Codex 模型列表中：

- **连接名 · 模型名称**：使用该连接与列表中的模型；未命名时显示模型 ID。同名模型属于不同连接时分别显示，使用各自凭据；切换不会改写插件委派的默认模型。

不再显示额外的「跟随 App 选择」。保存当前连接的新默认值后，尚在使用原默认模型的选择同步到新默认；在 Codex 手动选中的其他有效具体模型不受影响。已移除的模型回退到当前星标模型。默认选择写入 Codex 配置，现有对话中已经手动固定的具体模型不会被改写；重启后读取新的目录和默认设置。

左侧绿色「挟持中」标记表示最近一次请求使用的连接；尚无请求时显示默认连接。开启本身不会发送模型生成请求。

旧配置无需重建，仍显示原默认模型；旧默认路由和旧连接别名仅保留历史对话兼容，不出现在新目录中。已从列表移除的模型会停止接受新请求，重启 Codex 后从选择菜单消失。连接重命名后，请在 Codex 重新选择新连接名对应的模型。

一个 worker 对应一个连接，可以共用同一地址和 Key 勾选多个模型。保存并刷新 Codex 目录后，直接在 Codex 切换「连接名 · 模型名称」即可，不必回 App 更改默认。具体模型均使用固定标识，改变 App 默认值不会改变其路由；旧版仅包含连接名的别名继续跟随该连接默认模型。

本地网关仅监听回环地址，以随机令牌鉴权。Responses 接口逐块透传，替换模型别名和凭据，并在生成请求缺少输出额度时补入该模型的预算；只有其他接口才由本地 CPA SDK 转换，Codex 的登录信息和本地令牌不会转发给模型服务。原生 Responses 接口兼容性通常更完整，其他协议仍取决于模型的工具能力。图片能力由各模型独立声明，不宣称支持原生网络搜索。非 Responses 服务不支持 /responses/compact，Codex 使用本地上下文压缩。

**兼容策略**：CPA 推荐在连接信息中选择「Responses 透传」，将模型兼容交给上游；透传不使用厂商兼容策略。选择 Chat Completions 时，才在模型编辑窗口配置兼容策略，官方地址自动识别，自定义地址默认通用；直接转发厂商 API 时可指定 Gemini、DeepSeek、Kimi、豆包、MiniMax、GLM 等策略。策略同时用于插件和挟持模式；各型号思考开关与档位限制见[模型兼容说明](model-compatibility.md)。

**上下文长度**：在模型操作中打开「设置上下文」可填写覆盖值；新模型默认采用服务目录明确声明的容量与 256K（256000 tokens）中的较小值。关闭覆盖使用模型自带容量；上游未声明时保持未知，不按型号名称猜测。旧配置未设置开关时保留原兼容规则。详见[上下文容量](model-contexts.md)。保存连接，并明确更新接入配置后重启 Codex 生效。

已知容量的自动压缩阈值为容量的 90%；手动填写 `128000` 时约 `115200` tokens 压缩，关闭覆盖且容量未知时不写入臆造的阈值。「高级设置」的最大输出长度用于插件委派和旧接口转换，不会扩大上下文；Responses 透传的输出限制由 Codex 请求与上游决定。容量仍以实际 API 服务的限制为准，较长历史也可能增加请求费用。

挟持模式会暂存 Codex 顶层的上下文与压缩阈值覆盖项，让模型目录中的独立容量生效；关闭后恢复原值。其他 Codex profile 或启动参数仍可能覆盖目录。默认模型改为容量不同的模型后也需重启 Codex 刷新；在 Codex 中直接选择各个模型可使用其各自容量。

**思考标签与断流**：`<thinking>` / `<think>` 如果出现在普通消息里，说明收到的是正文文本；它们本身不是 Codex 的思考事件。标准思考字段会单独转换，普通正文不会用正则过滤，以免破坏引用和代码。透传不会额外插入限制标签或进度语言的提示，上游必须正确返回思考事件。Responses 透传不合成完成或失败事件；网络错误直接中止传输，是否缺少完成事件由 Codex 判断。本地挟持提供商使用 HTTP/SSE 并禁用 WebSocket，出现 WebSocket 错误时还需检查该对话实际使用的提供商与上游日志。

**最近请求**：在「使用帮助」展开「关闭后重新打开会使用什么配置？」后点击「查看最近请求」，可查看本次开启期间最多 20 条请求的完成、失败、超时或取消状态，以及安全请求 ID 和耗时。可复制脱敏摘要排错，不包含提示词、回答或凭据；HTTP 200 不会被直接标为生成完成。

**尚未交付内容时的短暂故障恢复**：桌面挟持网关的普通 `/v1/responses` 请求（包括 Codex 经此路径发出的自动上下文压缩）若收到上游 HTTP 502/503，且尚未向 Codex 输出响应头或正文，最多追加三次尝试，默认等待 2、15、45 秒。有效 `Retry-After` 可延长单次等待，最长一分钟；更长冷却直接保留原始错误，不提前绕过上游冷却。所有尝试共用原请求上游首包、空闲和任务时限，取消立即终止读取和退避，不自动更换连接、模型或思考等级。

**HTTP 200 的思考阶段也可恢复**：对不引用既有会话、非后台的安全流式请求，网关临时观察并保留最多 256 KiB 的开头元数据和思考事件。在尚未交付正文、实际工具调用或未知事件时，纯思考断流、空流和明确的瞬态上游失败可使用上述同一恢复预算；不会在 HTTP 重试之外另加三次。客户端函数、自定义工具、命名空间和内置只读网页搜索声明不会阻止这项恢复，但执行型服务端工具和未知工具类型会禁用它。一旦出现正文、实际搜索或其他工具调用、未知结构，或者达到缓存上限，就立即交付原始字节，并停止观察和自动恢复。思考片段的显示可能因此延后至首次正文或工具输出。

恢复成功只交付最后一次成功响应，不混入失败尝试的思考、响应头或请求 ID；恢复耗尽、冷却过长或剩余时限不足时，最后一次真实响应的状态、正文和请求 ID 原样保留。网关不修改 SSE 字节、不补完成事件，也不持久缓存思考历史。已交付正文或工具之后的断流、未获得 HTTP 响应的连接错误、401/403/429/500/504、`/responses/compact`、插件委派和执行型 worker 均不自动重试；鉴权、限额、上下文和参数失败事件也不会因错误文案而模糊重试。

重试能缓解短暂故障，但不能修复持续的供应方故障或没有备用账户的问题，也不保证失败尝试不计费。Codex 提供商自身的 HTTP 与流重试仍为零，避免叠加恢复次数。安装新 App 后才会使用该网关逻辑，正在运行的旧进程不会因源码修改自动更新。

关闭模式会恢复之前的模型设置，保留其他 Codex 设置的新修改。点击窗口右上角关闭时，会自动关闭挟持模式、取消进行中的模型请求并退出，无需先手动关闭开关。有未保存修改时，页面内弹窗提供「继续编辑」和「放弃修改并退出」。插件安装或配置操作进行中时，会提示等待完成。

恢复会比较启用前备份、App 写入值和当前配置，不再依赖注释标记逐字相同。换行、引号、字段顺序、显示名称，以及托管标记丢失或重复，都可在实际设置无冲突时自动处理。运行期间改选未被接管的独立提供商时，会保留新提供商和模型选择；仍属于托管模型的别名则恢复为原默认模型。其他设置和注释尽量保持原样。

检测到外部编辑后，恢复前会在本机 `codex-recovery` 目录额外保存当前配置与原始备份，成功恢复也保留这份快照。只有实际路由、协议、鉴权字段冲突，或配置格式无效等无法安全处理的情况才停止恢复；提示会指出冲突字段，不显示 Key。App 此时保持运行，备份保留，修复后可再次关闭。异常退出后，下次启动会尝试恢复。模式运行时请勿移动数据目录；使用其他 Codex 配置 profile 时，其覆盖项可能优先于此处的默认设置。

关闭后保留一个无密钥的历史对话提供商身份，复用 Codex 当前的账号或 API Key 登录及相应官方地址。**完全退出并重启 Codex** 后，在旧对话中改选该登录支持的官方模型即可继续；不能保留 `api-subagents/…` 模型。若要继续使用其中的外部模型，请重新开启模式并重启 Codex。新版按配置值兼容旧版端口 0 占位和账号兼容占位，格式或注释变化不再造成误报，并修复更早版本遗留的 `Model provider api_subagents not found`；不读取或修改聊天记录。若用户已将占位改成自定义提供商，关闭 App 时保留它；再次开启时会提示同名冲突，避免覆盖自定义设置。升级后请使用新版 App，旧版程序无法识别新版的兼容规则。

主对话内容、工具结果和代码会发送给所选模型服务。两种模式均使用外部 API 独立计费，本工具不读取套餐剩余额度。

## 本机数据

| 内容 | 默认位置 |
| --- | --- |
| 连接与 Key | `%LOCALAPPDATA%\CodexApiSubagents\models.json` |
| 委派记录 | `%LOCALAPPDATA%\CodexApiSubagents\tasks\` |
| Codex 配置备份与模型目录 | `%LOCALAPPDATA%\CodexApiSubagents\codex-*.json` |
| 外部编辑后的恢复快照 | `%LOCALAPPDATA%\CodexApiSubagents\codex-recovery\` |
| 插件运行程序 | `%LOCALAPPDATA%\CodexApiSubagents\runtime\` |
| 已安装插件 | `%USERPROFILE%\plugins\api-subagents\` |

`API_SUBAGENTS_HOME` 可指定数据目录，`CODEX_HOME` 可指定 Codex 目录。Key 和备份仅保存在本机；Git 与安装包不包含这些数据。备份可能包含原 Codex 配置中的私人字段，应和 Key 一样保管。

## 出现 Upstream request failed

如果上游日志中的模型是 `api-subagents/连接名/摘要`，并报 `unknown provider for model`，说明本地路由标识被直接发给了远程服务。仅在 Codex 中切换模型不会保证同时切换已打开对话的提供商，这与 API Key 泄露无关。

- 继续使用挟持模型：开启 App 的挟持模式，完全退出并重启 Codex。所有旧对话的提供商身份都临时指向当前网关，包括内置 OpenAI、非默认身份（例如 `custom`）及配置中已删除但历史元数据仍保留的身份。旧的真实模型名自动使用 App 当前选中的连接和默认模型，无须先把旧模型加入配置；显式选择 `api-subagents/…` 别名时仍使用该指定模型。App 收到请求后会显示「Codex 请求已接入本地网关」。
- 回到 Codex 账号模型：关闭挟持模式，完全退出并重启 Codex，在旧对话中选择账号登录支持的官方模型，不能继续选择 `api-subagents/…`；继续使用原来的外部模型则需重新开启模式。

每次重新开启时本地端口和令牌都会变化，因此不能只在第一次开启时重启。App 不会修改聊天记录或强制结束正在运行的 Codex。若上游错误不是以上内容，应按对应请求 ID 排查，不应一律归因于此问题。

## 图片与响应速度

在“模型选择 → 编辑模型 → 图片输入”选择自动、支持图片或仅文字。自动识别常见 GPT、Gemini 和 Claude 视觉模型系列，未知名称默认仅文字；自定义网关或别名可手动声明。这个设置只控制 Codex 上传入口，不能让不支持视觉的上游获得图片能力。保存后完全退出并重启 Codex 刷新模型目录；Responses 中的图片内容保持透传。

XHigh 和长上下文可能增加等待时间与费用，日常工作建议使用 low 或 medium。生成大文件时，模型可能一次返回很长的工具参数，Codex 要等参数完整才能执行，所以“正在思考”不等于整个时间都用于推理。首字耗时也取决于上游事件与网关计量方式，不能仅凭首字与总耗时接近就判断本地没有流式转发。

开启挟持模式会把全部已配置提供商、内置 OpenAI 和旧对话中的提供商身份临时指向同一本地网关。自定义身份禁用 WebSocket 并使用本地随机令牌；内置 OpenAI 通过 `openai_base_url` 和带随机令牌的专用回环路径接入，不创建 Codex 禁止覆盖的同名提供商表；若内置客户端尝试 WebSocket，会回落到 HTTP/SSE。原远程凭据暂存于本机，内置登录文件保持不变，转发时仅使用 App 中配置的 Key。App 只读查询最新会话索引及旧版活动、归档文件的首条提供商元数据，不读取聊天正文或改写会话身份。旧的真实模型名跟随 App 当前连接，显式本地别名保留用户指定的模型选择。退出模式或关闭 App 时恢复原来的地址、凭据和默认选择；启用前不存在的身份会删除临时条目，启用后另行添加的独立提供商及其他非托管修改仍保留。开关后需完全退出并重启 Codex；配置 profile 或其他软件覆盖托管字段时仍需先解决覆盖冲突。
