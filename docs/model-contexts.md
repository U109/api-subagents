# 上下文容量与自动压缩

当前实现以**服务模型目录明确声明的容量**为依据，不再按模型名称或厂商前缀推测官方规格。获取模型列表时读取 `context_window`、`context_length` 或 `inputTokenLimit` 中的有效整数值；没有这些字段时，容量显示为「待确认」。目录声明来自所配置服务，不保证该服务实际开放全部容量。

## 实际采用的容量

- 有明确声明：使用声明值与 **256K（256,000 tokens）** 中的较小值；不能在界面手动扩大。
- 无明确声明：保留旧配置中的有效手动值；没有手动值时使用兼容默认 256K。这只是本工具的兼容设置，不代表模型或网关承诺支持 256K。
- 自动压缩阈值为实际采用容量的 **90%**。上下文与最大输出额度分别配置，输出额度不会被误当成上下文。

| 服务目录声明 | 实际采用 | 界面说明 |
| --- | ---: | --- |
| 128,000 tokens | 128,000 tokens | 声明容量较小，不抬高 |
| 1,000,000 tokens | 256,000 tokens | 受本工具 256K 上限约束 |
| 未返回容量 | 旧手动值或 256,000 tokens | 待确认，不推测官方规格 |

## 保存与兼容

获取列表后，容量声明随连接草稿保存。刷新目录不会移除已选模型，但不再返回容量的模型会重新标记为待确认。未知容量仍可保留或填写 4096–2000000 的整数兼容值；已有明确声明时自动适配，旧手动值不优先于声明值。

保存修改后需完全退出并重启 Codex，以重新加载模型目录及压缩阈值。仅获取列表不会发送生成请求，也不会通过试探性模型调用来猜测容量。
