# 上下文容量与自动压缩

当前实现以**服务模型目录明确声明的容量**为依据，不再按模型名称或厂商前缀推测官方规格。获取模型列表时读取 `context_window`、`context_length` 或 `inputTokenLimit` 中的有效整数值；没有这些字段时，容量显示为「待确认」。目录声明来自所配置服务，不保证该服务实际开放全部容量。

## 实际采用的容量

- 新模型有明确声明时，默认启用「设置上下文」，采用声明值与 **256K（256,000 tokens）** 中的较小值；可在模型操作中调整覆盖值。
- 关闭「设置上下文」时不应用手动覆盖，使用模型自带的明确容量；没有容量声明时保持未知，不编造 256K 或压缩阈值。
- 旧配置尚未设置该开关时仍采用原兼容策略：明确声明优先并限制在 256K 内；未知容量保留有效旧手动值，否则使用兼容默认 256K。这不代表上游承诺支持该容量。
- 自动压缩阈值为实际采用容量的 **90%**。上下文与最大输出额度分别配置，输出额度不会被误当成上下文。

| 服务目录声明 | 实际采用 | 界面说明 |
| --- | ---: | --- |
| 128,000 tokens | 默认 128,000 tokens | 声明容量较小，不抬高 |
| 1,000,000 tokens | 默认 256,000 tokens | 关闭覆盖可使用原生声明容量 |
| 未返回容量 | 新模型保持未知 | 不按模型名称推测；旧配置保留兼容策略 |

## 保存与兼容

获取列表后，容量声明随连接草稿保存。刷新目录不会移除已选模型，但不再返回容量的模型会重新标记为待确认。手动启用覆盖时，可填写 1–2000000 的整数 tokens；关闭后保留原生声明，不应用手动值。容量仍受实际服务限制，手填更大值不会扩大上游额度。

保存修改后需完全退出并重启 Codex，以重新加载模型目录及压缩阈值。仅获取列表不会发送生成请求，也不会通过试探性模型调用来猜测容量。
